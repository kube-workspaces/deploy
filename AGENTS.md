## Commands

```
make install-crd             # install CRDs to current cluster (server-side apply)
make install-images          # apply Image CRs from images.yaml
make sync-images             # vendor images.yaml + helm files/ from image-catalog@IMAGE_CATALOG_VERSION
make check-images            # verify vendored images match IMAGE_CATALOG_VERSION
make deploy-kustomize        # deploy via Kustomize (base)
make deploy-crds             # deploy CRDs via Kustomize
make helm-install            # Helm install
make helm-upgrade            # Helm upgrade
make helm-template           # Helm template (dry-run)
make lint-helm               # Lint Helm chart
make auth-enable             # enable authentication
make auth-disable            # disable authentication
make port-forward-frontend   # port-forward frontend to localhost:3000
make port-forward-api        # port-forward API to localhost:8888
make port-forward-proxy      # port-forward proxy to localhost:8891
```

## Deployment Options

All target `kube-workspaces-system` namespace.

- **Kustomize:** `kubectl apply --server-side -k kustomize/base/`
- **Helm:** `helm install kube-workspaces helm/kube-workspaces/ --namespace kube-workspaces-system --create-namespace`
- **ArgoCD:** `kubectl apply -f argocd/application.yaml`

## Key Notes

- CRD is too large for client-side apply. Always use `kubectl apply --server-side` or `ServerSideApply=true`.
- Images are defined as `Image` CRs (cluster-scoped). Default images in `images.yaml`, vendored from `kube-workspaces/image-catalog` — do not hand-edit, see Image Catalog Sync below.
- CRD YAML files in `kustomize/crds/` are synced from the controller repo's `config/crd/bases/`.
- Docker images: `ghcr.io/kube-workspaces/{controller,api,proxy,frontend}` on GitHub Container Registry.
- Image defaults (defaultEnv, defaultArgs, etc.) are applied at workspace creation time only.
- `defaultEnv` supports `{{namespace}}` and `{{name}}` placeholders.
- Auth is opt-in (disabled by default). Use Helm `auth.enabled: true` or `make auth-enable`.
- PlatformConfig CRD is cluster-scoped singleton named `default`.
- Helm installs a curated 5-image subset by default (`installExampleImages: true`); set `installCatalogImages: true` for the full catalog.

## CRD Sync

CRD YAML is generated by the controller repo. When CRDs change:
1. In the controller repo: `make manifests`
2. Copy `config/crd/bases/kubeworkspaces.io_*.yaml` to this repo's `kustomize/crds/`
3. Commit and push

## Image Catalog Sync

`Image` CR manifests are owned by `kube-workspaces/image-catalog`, not this repo. To pick up a new release:
1. Bump `IMAGE_CATALOG_VERSION` in `Makefile`
2. Run `make sync-images`
3. Commit `images.yaml` and `helm/kube-workspaces/files/images-*.yaml`
